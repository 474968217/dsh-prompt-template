# DSH 提示词模板

[English](README.md)

在 DeepSeek Harness 输入框旁添加 **提示词** 按钮。选择常用提示词后插入当前光标位置，按需修改，再由你发送。

## 功能

- 自定义创建、修改和删除模板，支持名称、正文和单层标签。
- 浮层内搜索名称、正文和标签，支持 ↑ / ↓、Enter 和 Esc。
- 为单条模板设置全局范围，或指定多个项目目录。
- 管理列表支持标签勾选筛选，可与关键词搜索组合。
- 置顶模板，拖动行首手柄调整顺序；也可使用键盘移动。
- 从全库复用已有标签，自由输入新标签，或移除已选标签 chip。
- 数据由 DSH 宿主持久化，同一宿主的会话共享模板。
- 中英文界面，样式跟随 DSH 主题。
- 仅插入纯文本，不自动发送；成功插入后可一步撤销。

首次空库提供 6 条可修改的工程提示词：理解代码与调用链、最小变更实现需求、先定位根因再修 Bug、只报有证据的代码审查、补有价值的测试、完成前做证据验收。均为全局范围，调试、审查、验收三条默认置顶。升级不覆盖或自动增补已有模板库；删除全部模板后保持空库，不会自动补回。

提示词为中文原创精简改写，参考 [Superpowers](https://github.com/obra/superpowers) 的系统化调试、完成前验证方法及 [PGP](https://github.com/jgamblin/PGP) 的审查维度，不是原文复制，也不包含完整技能的工具流程。

## 环境要求

- DeepSeek Harness `>=0.2.3-alpha.2 <0.3.0-0`，启用 Web 界面相关服务（包括桌面端内置 Web 界面）。
- 从源码检查与测试时需要 Node.js 20 或更新版本，无需构建，无第三方运行时依赖。

当前版本基于 DSH `0.2.3-alpha.2` 开发。

## 安装

打开 DSH 插件管理页面，以 GitHub 包方式添加。到本仓库提交记录中复制所需版本的 **完整 40 位 commit SHA**：

```text
github:474968217/dsh-prompt-template#<完整40位commit-SHA>
```

将占位内容替换为真实提交 SHA，分支和 tag 不能替代不可变提交引用。安装后根据插件管理器返回的激活提示操作。

本地开发时，通过插件管理器安装本仓库的绝对目录，DSH 会链接该目录。修改已安装包的文件后，重新启用其插件条目可触发重组和重新载入；以工具返回的激活结果为准。

## 使用

1. 在输入框放置光标或选中文字，然后点击 **提示词**。
2. 输入关键词并选择模板，Enter 插入当前选中项，Esc 关闭。插件不会自动发送。
3. 点击底部 **管理模板…**，新建、编辑、置顶或调整模板顺序；删除前需要确认。
4. 项目模板选择 **指定项目** 并勾选一个或多个目录。编辑时可以修改生效范围。

管理面板左侧用于选择与排序，右侧当前模板标题区集中放置置顶和删除操作。删除确认显示模板名，保存与取消固定在编辑区底部。窄窗口采用列表/编辑单栏切换，返回时仍保护未保存修改。

管理列表可以组合关键词与标签勾选：模板必须同时满足关键词和任一已选标签。标签候选始终来自完整模板库，不受当前列表筛选影响。编辑时可点击已有标签复用，或自由输入后按 Enter、点击 **添加标签**；新输入可用逗号分隔。直接保存也会一并提交尚未添加的输入文本。已选标签通过 chip 移除。每条模板最多 6 个标签，每个最多 20 字符；会去除首尾空白并忽略大小写去重。

拖动行首手柄调整顺序，或聚焦手柄后按 ↑ / ↓；筛选时仅调整可见项，隐藏项位置保留。

项目匹配以会话的 **完整工作目录** 为准，比较前做路径规范化。`/work/app` 的模板不会自动出现在 `/work/app/subdir`，Windows 路径比较不区分大小写。管理面板可以管理其他项目的模板，选择浮层只显示当前会话可用项。

打开浮层时会捕获原插入位置。如果选择前草稿已经变化，插件会拒绝插入并提示重新选择，避免覆盖新内容。重新打开浮层即可捕获新的位置。原来选中的输入框文字通过同一个可撤销动作替换。

## 数据与升级

数据保存在 DSH 宿主侧，不依赖浏览器本地存储，也不会写入本 Git 仓库。刷新页面不会重置模板。卸载插件不会主动删除宿主中的模板数据。项目范围用于控制模板在哪些会话中显示，不是宿主用户间的权限隔离机制。

升级时，在插件管理器中将 GitHub 安装引用更新为目标版本的完整 commit SHA，保留同一包名与宿主存储。若 DSH 拒绝兼容版本范围，请使用兼容的插件版本。

单层标签模型可以读取 v1 旧库；纯读取转换不改写介质、不增加 revision。旧 tags 保留顺序和首次出现的拼写，非空旧分类作为一个完整标签追加在后，即使含逗号也不拆分，再去除首尾空白并忽略大小写去重。首次成功的正常写操作（保存、删除、置顶、排序或记录使用）会把全库按 canonical 单层 tags 写入存储域 v2。旧 v1 reader 会拒绝该文件，因此降级前应保留备份。转换不覆盖用户模板，也不恢复已删除的默认项。

## 开发

```sh
npm run check
npm test
npm pack --dry-run
```

宿主入口为 `lib/index.js`，数据模型为 `lib/store.js`，客户端入口为手写 `window.__ModuleLoader__` 包装的 `lib/client.js`。React 来自 DSH 提供的模块表，不向页面安装第二份 React。

工具栏使用 `conversation.input.left`，条目 id 为 `prompt-template-trigger`。浮层使用 React portal，避免被吸底输入框裁切；资源随 Cordis 上下文销毁。

详见 [实现计划](docs/plan.md) 与 [验证记录](docs/verification.md)。`docs/mockup/` 中的文件为设计参考，不代表已安装插件的真机截图。

## 已知限制

- v0.1 不提供变量替换、Markdown 预览、导入导出、斜杠触发或全局快捷键。
- 数据由单个 DSH 宿主进程管理，不支持多进程同时写入同一存储。
- 项目路径精确匹配，不同工作树按不同目录处理。
- 远程工作区和自定义文件系统工作区行为尚未验证。
- 无浏览器控制连接时，安装后的布局、主题切换和完整管理流程仍需交互验收；具体已测项目见验证记录。
